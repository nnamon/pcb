# Review 23: pcb 0.6.1 (released) and 0.7.0 (the copper graph)

Independent reviewer, 14 Nov 2026: `v0.6.1` and the uncommitted work on branch `pcb-0.7.0`. The reviewer was given the files and the claims, not the reasoning, and read the code without running it. The report is as written; the closures follow it.

## Report

Read-only review; nothing was run, so every finding is from reading the code. Freerouting's and KiCad's own behaviour is unverified.

### A. pcb 0.6.1 (released)

1. **BLOCKER, `src/route.rs:787-793` and `:848-849`.** With `--project` and any `class = "critical"` net, a run with no `--nets` sets `o.nets` to every non-critical net, and `--rip all` becomes `Rip::Nets(all)`. `named()` is then true for every zone net, so `zone_owned` is empty. GND's stitching vias are ripped and GND is not in a `pcb_plane` class, which is the fault 0.6.1 says it removed. Fix: compute `named` from the user's original `--nets`/`--rip` before the rewrite at 779-793.

2. **SHOULD-FIX, `src/route.rs:935`, `:1279`, `:1353`.** `plane_nets` still holds every zone net, including one the run names. `--rip GND --nets GND` rips GND, passes `--router.plane_nets=GND` to Freerouting, allows any growth in GND `unconnected_items` at the gate, and keeps GND out of `still_open`. This contradicts "routed as tracks, zone or not" in DESIGN and CHANGELOG. Fix: use `zone_owned` for the Freerouting argument, `plane_allow`, `judged` and `still_open`.

3. **SHOULD-FIX, `src/route.rs:1223-1224`, `:1353`.** A zone net with pads outside its fill is dropped silently, for example a +3V3 power fill round the regulator with +3V3 pads elsewhere. It is in an ignored class, excluded from `judged` and `still_open`, and `plane_split` only lists counts that grew. `--staged` inherits this: stage 2 routes only `r1.still_open`. Fix: report zone nets with `unconnected_items` after the gate as a warning naming `--nets NET` or `pcb zone`.

4. **NOTE, `src/route.rs:923-926`.** `--nets N` on a board whose class holds only N and GND makes `pcb_not_routed_0 = {GND}`. The `pcb_plane` pass then empties and deletes that class, but its name stays in `ignored`. `freerouting.rs:62` says pcb names only classes it wrote. Fix: run the plane pass first, or drop emptied names.

5. **NOTE, `src/route.rs:411-433`.** `width_classes` reads only the first class. Dropping the clearance is right only if that class is KiCad's default, whose clearance equals the structure rule's. A net in a KiCad netclass with its own clearance is never moved, and that class still carries `(clearance …)`, so by the stated mechanism it still loses `via_via`. The doc comments at `:410` ("same vias and clearance") and `:441` ("the DSN's largest via") are stale.

6. **NOTE, `src/route.rs:371`.** I found no fault in `unique_images`. It handles quoted names, touches only `(component `/`(image ` lines, and `read_ses` reads only `routes/network_out`, never image names. A collision needs a footprint literally named `X__variant_N`. It rewrites CRLF to LF.

### B. pcb 0.7.0 (uncommitted)

7. **BLOCKER, `src/copper.rs:130-164`, `:237-240`.** A fill is a clique of edges, not a node (DESIGN says "fills are the nodes"). Take pad A, an F.Cu track, via V1 into a B.Cu fill, via V2, an F.Cu track, pad B, with nothing but vias touching the fill. V1's only non-via neighbour is its track, so `sides.len() == 1` and there is no finding at 5 A through one 0.3 mm via. That is the supply-into-plane layout the check exists for. Fix: make each filled polygon a node for `groups`/`via_bridges`.

8. **SHOULD-FIX, `src/copper.rs:115-117`.** A via joins a track only at the track's end. Take F.Cu (0,0)-(12,0) and B.Cu (8,0)-(20,0) with vias at (9,0) and (11,0): neither joins, so the net reads open, with no finding and no loop. An `add_via` on the middle of a track, which the `fix` text invites, does not clear the finding. Fix: join when `point_seg_dist(via, seg) <= size/2`, checking `v.layers`. Blind-via layers are ignored at `:116`, `:124` and `:154`.

9. **SHOULD-FIX, `src/copper.rs:84`, `:12`.** A track counts whole, so the length is not a lower bound. A capacitor stub and an IC stub that T into a 40 mm trunk 2 mm apart read as a loop of more than 40 mm, a false `decap-loop`. Fix: split tracks at junction points in `build`. README and DESIGN say "lower bound".

10. **SHOULD-FIX, `src/copper.rs:231-249`.** Two faults in the grouping:
    - **False finding:** `current_a` is applied to every branch. A 10 k pull-up on a 2 A +3V3 net, reached through one via, is a finding.
    - **Missed finding:** on four layers, pieces P1 and P2 joined by V1, plus V2 from P1 to an In1 track and V3 from that track to P2. That is three groups, none of which parts the pads, so 5 A over two 1.41 A paths passes. This needs a min-cut, or a documented limit.
    - A through-hole pad in parallel suppresses the finding correctly. `via_amps(0.3)` is 26.3 mil² and 1.41 A, which is right.

11. **SHOULD-FIX, `src/copper.rs:324-327`, `:329`; `src/quality.rs:269`.** Three gaps in `unreferenced`:
    - A board with no ground zone, or with unfilled zones, returns `None`, so `max_unreferenced_mm = 5` passes with no ground at all. Fix: count the whole length bare when a limit is set.
    - Arcs are not measured; only `b.tracks` is read.
    - A critical net missing from the board is reported as `0/0`.
    - `stack` and `under` are right for 2, 4 and 6 layers. Inner tracks are skipped. Fractured filled polygons handle holes.

12. **NOTE, `src/copper.rs:276-312`, `src/circuit.rs:123`.** The loop is per supply net: VDD pin 20 with no capacitor is hidden by pin 1's. `Loop`'s doc says "pin". Another IC's capacitor on the same net is a candidate; it wins only when nothing is nearer. These cases are skipped silently:
    - no `[project] netlist`;
    - a `.net` with no `pinfunction`/`pintype`;
    - a capacitor on AGND with the IC on GND;
    - unfilled zones.
    - Fix: emit a warning listing the ICs not measured.

13. **NOTE, `src/circuit.rs:208`.** `CC1101_GDO` is not matched. `CC2_EN` paired with `CC1_EN` on a `J`/`P`/`X` part is. `A5_CC1` is not. Fix: accept `CC[12]` alone or next to an `[AB]\d+` token.

14. **NOTE, wiring.** I found nothing wrong in the `src/check.rs` wiring: `at` takes the last two words, so net names with spaces work; `add_via` exists (`src/edit.rs:38`); the waiver name and the three schemas match what is serialized.

### Tests

15. **SHOULD-FIX, coverage.**
    - **No test at all:** `without_planes`; the absent clearance (`wide_nets_get_their_own_class` doesn't assert it); findings 1-4, 7, 8 and 10; arcs; 4-layer `stack`; a through-hole pad in parallel; multi-pin decap; the `cc_name` negatives; a `via-current` waiver.
    - **Weak:** the `unreferenced` case asserts only `0 <= bare <= track`. 0.6.1's only case is the existing `zoned_rip_all`.
    - **`lcsc_same_package`:** the reason is true, since 10 k on CC1 is now a `usb-cc` finding. But the case no longer covers a code and value changing together. Keep both edits on a resistor that is not a CC pull-down, or waive `usb-cc J1 CC1`.
    - **`sch_after_gate` (`tests/cases/m4_cases.py:1081`):** it sets R1 to 4.7 k and can now fail the release through `usb-cc` rather than the gate.

### Docs

16. **SHOULD-FIX, docs.**
    - DESIGN "fills are the nodes" and "lower bound" are wrong (findings 7 and 9).
    - CHANGELOG 0.6.1, DESIGN and the bench doc put the 0.46 mm via pair down to the class clearance. The comment at `src/route.rs:450` puts it down to the widest ring, and no doc mentions the max-to-min ring change.
    - CHANGELOG 0.7.0 doesn't say to move the pin to `"0.7"`.
    - STYLE: "DRC says whether a net is in one piece; the graph says how" (DESIGN, `copper.rs:2`) is antithesis as rhythm. The last paragraph of "Against 0.6.0" in `docs/bench/route-0.6.1.md` narrates the earlier file's mistakes (rule 7).

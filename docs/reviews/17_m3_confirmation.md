# Review 17: confirmation of review 16 (milestone M3)

Independent reviewer, 5 Nov 2026, worktree at commit 32de5fc (merge of `pcb-m3-import` into `pcb-m4`), binary built from that tree. Probes in `tests/review17/`, verdicts in `tests/review17/check.py`: 37 verdicts pass, 4 fail (39 twice, 40, 41), 9 notes. Exit 1.

All 12 closures hold for what they claim. Three new findings could let a bad board reach ordering. The `stale` check records that zone, paste and art ran on the current pcb.toml, but never checks that their output is still on the board (39). Release fills zones with the board's own rules, while pcb check's fab run judged a fill made with the fab's rules. A 4-layer board ships inner copper 0.2 mm from another net's component hole against the fab's 0.3 mm (40). A `[[place]]` entry changed and not applied passes check (41).

| 39 | FINDING | The `stale` check compares pcb.toml with the hash the last run recorded. It never checks that the run's output is still on the board. Board edits after the run that undo it keep the record and pass. Evidence: (1) the `pcb:art:label12` group (the `v{version}` label) deleted in pcbnew after `pcb art`: check `done`, gate passes, release `done` with no warning. The released F.Silk differs from the control release in 6 places, and the board carries no version. (2) U1.57's paste windows undone, as a footprint update from the library does (4 aperture pads removed, F.Paste restored on pad 57): check `done` (the `paste` rule sees a paste opening), release `done` with the full exposed-pad paste the `[[paste]]` rule exists to prevent. F.Paste differs from the control release. Fix: in `pcb check`, rerun zone, paste and art on a copy and require the copy's affected items to equal the board's. At least, compare each `pcb:art:<name>` group's geometry, and each `[[paste]]` pad's layers and aperture pads, with what the command would write. This is review 16's suggested fix for 29. | `stale17` `label_deleted`, `paste_undone` |

Fix: in the fab run, fill with the board's rules (as release does), then put the fab rules in place and run DRC without `--refill-zones`.

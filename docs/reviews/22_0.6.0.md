# Review 22: pcb 0.6.0 (ERC, circuit checks, part search, routing additions)

Independent reviewer, 14 Nov 2026, the uncommitted work on branch `pcb-0.6.0`. The reviewer was given the files and the claims, not the reasoning, and read the code without running it. The report is as written; the closures follow it.

## Report

Review of the uncommitted 0.6.0 changes in /Users/amon/projects/pcb/pcb. No BLOCKER found. Everything below is from reading the code; the only things executed were a Python port of `ohms()` and a look at one recorded `erc.json`.

### Findings

1. **SHOULD-FIX, src/circuit.rs:169 (`led-resistor` rarely fires on a real board).** The test is "any `R`/`RN` on either terminal's net", so any resistor anywhere on GND or the rail satisfies it. Input: `D1` between a GPIO net and `GND`, no series resistor, plus one 5.1 kΩ CC pull-down to `GND`: no finding. The unit test and the `circuit_led` case pass only because their netlists hold no resistor. Fix: judge only the terminals that are not ground or a rail, and flag when both are.

2. **SHOULD-FIX, src/circuit.rs:64 (`ohms` reads only the first word).** `"5.1 kΩ"` and `"5.1 k"` give 5.1, so a correct board gets `usb-cc J1 CC1 ... pulled down by R1 (5.1 kΩ); a device's pull-down is 5.1 kΩ`. Fix: join a second word that starts with a multiplier or Ω.
   - Also `"2m"` gives 2.0, because the trailing `m` is trimmed as part of "ohms"; `"1E3"` gives 1.3.
   - Correct: `5.1k`, `5k1`, `5.1kΩ`, `0R`, `0`, `4.7K 1%`, `1M`, `100` parse; `DNP`, `""`, `NC` give None.

3. **SHOULD-FIX, src/check.rs:166-171 (`fix` strings name things that don't exist).**
   - `paste-unassembled`: `[[paste]] ref = "X", no_paste = true`. `PasteRule` (src/project.rs:222) has `pad = "REF.PAD"`, no `ref`, and `deny_unknown_fields`, so following the fix gets pcb.toml refused.
   - `via-in-pad`: "a `move` op". The op is `move_via`.
   - `width-current`: "a `width` op". The op is `set_width`. It takes the item's first word as the net, so net `P W` gives `--rip P`. It should now say `pcb route --project . --rip NET`.
   - `--rip`, `[[place]]`, `pcb paste`, `pcb sync`, `pcb zone` exist.

4. **SHOULD-FIX, src/circuit.rs:139-146 (usb-cc false positive).** `J1.CC1 — R (0 Ω or series) — U2.CC1`: the CC net holds only J1 and R, so there is no controller, pull-down or pull-up, and it reports "no 5.1 kΩ and no controller". Fix: follow one series part to its far net.

5. **SHOULD-FIX, src/circuit.rs:58-59, 121 (decoupling false positive).** With pin type empty or `passive` (JLCPCB/EasyEDA symbols), any token starting `VIN` is a supply pin: `VIN+`, `VIN-`, `VINP`, `VINL` on a current-sense amplifier, ADC or codec give "U3 is supplied from SHUNT_P". Fix: match whole tokens, or `VIN` plus digits only.
   - Also flagged: a rail reaching the IC through a 0 Ω link or bead with the capacitor on the far side.

6. **SHOULD-FIX, src/circuit.rs:43-55, 175-186 (hierarchical names).** Tokens come from the whole path.
   - `/sensors/SDA` is not I2C by name (`SENSORS` fails the `all`), so it is missed unless a pin is named exactly `SDA`. `SENSOR_SDA` and `SDA_3V3` are missed too.
   - Every net in a sheet `/pwr/…` or `/vbus_sw/…` is a rail, and `PWR_EN`, `PWRGOOD`, `VBUS_DET` are rails, so a resistor to one counts as a pull-up or a CC source.
   - Fix: test the last path component; drop the bare `PWR` prefix.
   - `VSENSE` is neither ground nor rail, which is correct.

7. **SHOULD-FIX, src/main.rs:684 with src/route.rs:869 (staged run and `--width`; older than this diff).** Stage 2 clones `widths` with `nets = still_open`, so `--staged --width V=0.4` is refused (`usage`) whenever V closed in stage 1, after stage 1 has written the output and without restoring it. Fix: filter `widths` to the stage-2 nets.

8. **NOTE, src/main.rs:658 (`current_a` width).** The width is the widest over all `--layers`. 1 A with an inner layer allowed is about 1.57 mm on every layer, and in stage 1 of `--staged` (F.Cu alone) too, where 0.31 mm is enough. Precedence itself is as claimed, and pcb.toml nets absent from the board or the run are skipped.

9. **NOTE, src/route.rs:1258-1279 (partial keep).** `net_of` handles quotes, spaces and parentheses. No underflow: the counts come from the same lines. `.rejected` is removed or rewritten correctly, and `still_open` comes from the second gate.
   - `l.edits` still holds tails pruned and prewire free ends trimmed because of the dropped copper, so "stay as the input had them" (DESIGN) is not exact; the gate catches only what DRC counts.
   - `pruned_segments` and `split_tracks` are not adjusted.
   - In `--staged`, stage 1's `dropped_nets` and its warning are lost when stage 2 runs.

10. **NOTE, src/check.rs:259 against DESIGN.md.** The DRC `at` is the own-rules run's first violation when both runs have the key; DESIGN says "from the fab-rules run when the two runs differ".

11. **NOTE, src/check.rs:148 (`place_of`).** A net named like a part (`SW1`, `LED1`, `D2`) gives a `width-current` finding that part's centre. A ring finding on a netless via gets no `at` (three words).

12. **NOTE, src/check.rs:270.** With no `[project] netlist`, neither `erc` nor `circuit` runs and nothing says so. A missing netlist file now makes `pcb check` refuse.

13. **NOTE, src/parts.rs (search).** The schema matches the serialised report, including `stock >= 1` with `--standard`.
    - A JLCPCB reply with `data: null` or an error code gives "0 part(s)", outcome done. Check the reply's code.
    - A missing `componentProductType` is counted as Standard-only; `pcb parts` calls it `economic-unknown`.
    - check.json, gate.json, parts.json and route.json match the new fields.

14. **NOTE, src/parts.rs:354 (Preferred).** With only Preferred Extended parts nothing is said, which is acceptable since `data.parts[].preferred` shows it; README's "named after them" holds only when another Extended part exists. The fee waiver is Economic-only by the code's own comment, yet `service = "standard"` is not consulted.

15. **NOTE, circuit, other.**
    - DNP parts count as present.
    - Crystals with reference `X`, RTCs with built-in load capacitors and 3-pin resonators are flagged or skipped by prefix.
    - `USBC1` is not a receptacle prefix.
    - The LED footprint test is a substring (`ANGLED`, `SHIELDED`).
    - No panic found: the slices are on ASCII tokens and the indexes are guarded.

16. **NOTE, tests.** Cases in `tests/cases/` exist for `decoupling`, `led-resistor`, erc `pin_not_connected`, `erc-skipped`, the waiver, `at` on a part, Preferred, search (three), partial keep and three width cases.
    - Unit test only, no case: `usb-cc` (all four branches), `i2c-pullup`, `crystal-load`, the raised ERC warnings, Basic/Preferred/Extended order through the CLI.
    - No test at all: `erc-warnings`, ERC `excluded`, `at` for `REF.PAD`, ring via and DRC, every `fix` string but "schematic", partial keep's still-worse fallback, staged with project widths, inner-layer width, a critical net with `width_mm`, Preferred-only parts.

17. **NOTE, docs.**
    - docs/codes.md has all five new codes; its `kicad-cli` row still says only "could not export the netlist".
    - CHANGELOG heading "0.6.0 (14 Nov 2026): the circuit, part search, and what a comparison with Copper showed" is a colon subtitle (STYLE 22); 0.5.1 has none.
    - DESIGN "goes to the place with `pcb render --region` or `pcb info`": `pcb info` takes a reference or net, not a place.
    - README coverage row says "not their values"; usb-cc checks one.
    - docs/bench has a Seconds column (STYLE 18) and a "What it shows:" setup.
